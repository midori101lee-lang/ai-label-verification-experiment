# AI 标识实验 Demo · 正式实验网页

> 毕业论文《AI标识如何影响用户的信息验证行为——基于信息加工机制的实验研究》的**正式实验网页**。
> 用途：在公网回收参与者的**真实核查行为**，并通过匿名编号与问卷星量表衔接。实验网页**只负责**随机分组、新闻阅读、核验行为记录、编号生成与本地导出；正式问卷（理解/卷入/可信度/一致性/可核验/错误判断/AI 标识操纵检验/VOI/AI 态度/人口统计）统一由**问卷星**托管。材料为 3×2 被试间设计（AI标识 × 信息一致性）。

## 实验设计（3 × 2）

| 自变量 | 水平 | 说明 |
| --- | --- | --- |
| **AI_label**（AI标识） | 0 = 无标识 ｜ 1 = AI辅助生成 ｜ 2 = AI生成 | 文本开头灰色标识「AI辅助生成」/「AI生成」，无 ⓘ、无展开说明；三条件视觉规格一致 |
| **evidence_consistency**（内容证据一致性） | 0 = 一致 ｜ 1 = 冲突 | 一致：两项结果方向一致；冲突：第一项明显改善、第二项只有较小变化 |

六个条件：0/0、0/1、1/0、1/1、2/0、2/1。选题：手机「护眼模式」对视疲劳的作用。

## 参与者流程（实验模式，默认显示）

`知情同意 → 固定随机分组（编号与条件绑定）→ 阅读新闻 → 核查任务 → 完成页（问卷星引导 + 本地导出）`

- **正式问卷移交问卷星**：实验网页不再采集任何问卷题项（理解题、操纵检验、开放题等）；完成页引导参与者前往问卷星填写，并通过匿名编号（`participant_id`）关联两份数据。详见 `docs/问卷星衔接与数据合并说明.md`。

- **知情同意前置**：勾选同意后才分配条件，符合正式实验伦理前置。
- **条件固定**：随机结果写入本机会话（`exp_session`），刷新/后退可恢复，**不会静默重分配**。
- **核查任务（核心）**：参与者可点开 4 份补充材料，系统记录到达/打开/关闭/顺序/次数/停留/明确"暂不查看"等完整事件流；状态严格区分 `not_reached / opened / declined / skipped`。
- **主因变量**：`verification`（至少打开 1 份 = 1）。⚠️ 这表示"启动核查/主动信息寻求"，**不等于**完成独立交叉验证；停留时长仅作日志，不证明阅读深度（论文须明确此边界）。
- **数据保存**：默认仅本机 `localStorage`（`exp_records` / `exp_session`），刷新不丢失；换设备需参与者下载/复制记录或用完成页引导回填问卷星。**数据可能因清缓存/换设备/浏览器故障丢失，不能视为集中回收。**
- **参与者端导出（统一 XLSX）**：完成页提供「下载我的实验记录（XLSX）」生成 `experiment_<participant_id>.xlsx`（含 `participant_summary` / `event_log` / `raw_json` 三表），用于上传至问卷星必答文件上传题；另保留「下载原始 JSON（备用）」。详见 `docs/数据字典.md` 第四节。
- **在线集中保存（可选）**：默认关闭。启用后，完成提交会 POST 到 `EXP_CONFIG.DATA_ENDPOINT`；**必须等待服务端返回 `{ok:true}` 才视为成功**，失败仅提示并提供「重试同步」，绝不虚报成功。服务端使用 **Cloudflare D1（真实持久化数据库）**，以 `participant_id` 幂等写入，并配套**受保护的研究者后台**（`/admin`，密码 → HMAC-JWT 登录，支持列表/计数/单条详情/批量 JSON+CSV 导出）。详见 `docs/服务端部署与后台说明.md`。

## 两种模式

### 实验模式（默认，参与者视图）
上述参与者流程。不暴露条件名/条件码，不显示对错。

### 研究者模式（低存在感「研究者」按钮，被试不可见）
页面右下角半透明「研究者」按钮，点击后展开：
1. 刺激材料对比（6 条件矩阵 + 证据速览行开关）
2. 被试完整流程（演示用，含操作检验、核验机会、最终判断）
3. 数据与导出（演示内存记录 JSON/CSV）
4. 实验纯净度审计（14 项）
5. 分析与风险
6. 材料理解自检
7. **实验参与者数据**（只读的本地浏览器视图：编号、条件、状态、时间、到达阶段、核查状态；**无下载按钮**，下载统一由参与者端 XLSX/JSON 完成；仅当前浏览器记录，不跨设备汇总）

> 研究者模式下「证据速览行」默认关闭；正式实验前请确认其为关闭状态。

## 配置（研究者修改 `index.html` 顶部 `EXP_CONFIG`）

| 字段 | 含义 | 默认 |
| --- | --- | --- |
| `SURVEY_URL` | 问卷星正式问卷地址；填后完成页自动带入编号 | `""`（留空则仅显示编号与手动回填说明） |
| `SURVEY_ID_PARAM` | 问卷星接收编号的参数名 | `"pid"` |
| `DATA_ENDPOINT` | 集中保存服务端地址（需部署 Worker）；留空则纯本地 | `""` |
| `SCHEMA_VERSION` | 数据格式版本 | `"exp-v2"`（exp-v2 起实验网页不再采集正式问卷题项，相应字段已迁移至问卷星） |

## 本地打开 / 部署

- 本地：`python3 -m http.server 8000` 后访问 `http://localhost:8000`（或直接双击 `index.html`）。
- 部署：GitHub 仓库 `ai-label-verification-experiment`（public，独立仓库） + Cloudflare Pages，Build command 留空，输出目录为项目根。详见历史 README 的部署步骤。

## 数据伦理

- 不收集姓名、手机号、邮箱、身份证、学校、IP 等任何个人身份信息。
- 参与者仅被分配匿名 `participant_id`（随机生成）。
- 材料条件仅研究者可见；参与者页面不显示。
- 本仓库**不包含**任何真实被试数据。

## 测试

- 前端静态自动化测试：`node tests/run-tests.mjs`（校验脚本语法、6 条件渲染正确性、`deriveVerifyStatus` 全分支）。
- 服务端逻辑模拟测试：`node tests/run-server-tests.mjs`（用内存存储驱动真实 `app.handle` 逻辑，覆盖提交/幂等/校验/鉴权/导出/CORS）。
- **未部署验证**：D1 实际 SQL 执行、真实浏览器交互、线上端到端均尚未进行，不标记为已完成。正式预试前请按 `docs/服务端部署与后台说明.md` 第六节部署并做真实验收。

- `tests/run-tests.mjs`、`tests/run-server-tests.mjs`：测试。
