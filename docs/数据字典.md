# 实验数据字典（exp-v1 / exp-v2）

> 适用对象：`exp_records`（本机 localStorage，键 `exp_records`）与参与者完成页下载的 XLSX / JSON。
> 每条记录 = 一名参与者的完整实验会话。**不含任何个人身份信息**。
> 数据格式版本由每条记录的 `schema_version` 字段标记，便于跨版本解析。

> **schema 版本说明**
> - **exp-v1**：实验网页同时采集正式问卷题项（Q1–Q4、AI 标识操纵检验、开放题，以及临时加入的阅读理解题 `q_reading_*`）。
> - **exp-v2**（当前）：正式问卷统一由**问卷星**托管，实验网页**不再采集**上述问卷题项；相应字段（`q1`、`q2_consistency`、`q3_resolvability`、`q4_false_info`、`ai_awareness`、`ai_manipulation_check`、`open_feedback`、`q_reading_*`）已从会话与导出中移除。历史 exp-v1 导出的 XLSX/JSON 仍保留这些列，可作版本区分与兼容读取。
> - 本字典顶层与 `participant_summary` 字段以 **exp-v2** 为准描述；exp-v1 多出的问卷列见文末「历史 exp-v1 字段」一节。

> **服务端存储说明**：启用在线集中保存后，记录以 `participant_id` 为主键写入 Cloudflare **D1**（真实持久化数据库），`raw_json` 列保存完整原始记录（含 `verify.events`）。研究者后台的 CSV / JSON 导出**直接来自服务端存储**，与参与者提交内容一致；嵌套原始事件不丢失（CSV 无法表达的字段可经配套 JSON 获取）。详见 `docs/服务端部署与后台说明.md`。

## 一、顶层字段（exp-v2）

| 字段 | 类型 | 取值 / 编码 | 说明 |
|---|---|---|---|
| `schema_version` | string | `"exp-v2"` | 数据格式版本 |
| `participant_id` | string | `EXP-XXXXXXXX` | 匿名研究编号（随机生成，与编号绑定条件） |
| `AI_label` | int | `0`=无标识 ｜ `1`=AI辅助生成 ｜ `2`=AI生成 | **实际随机分配到的** AI 标识条件（`assigned_condition` 的 AI 维度） |
| `evidence_consistency` | int | `0`=一致 ｜ `1`=冲突 | **实际随机分配到的** 信息一致性条件 |
| `news_version` | string | `"AI_label=x · evidence_consistency=y"` | 实际呈现的新闻材料版本（便于人工核对） |
| `consent_given` | bool | `true` | 是否勾选知情同意后开始 |
| `consent_ts` | int | epoch ms | 知情同意时间戳 |
| `status` | string | `in_progress` ｜ `completed` | 会话完成状态 |
| `step` | int | `1`–`4` | 到达的步骤（用于刷新恢复） |
| `started_at` | int | epoch ms | 开始时间戳 |
| `last_active` | int | epoch ms | 最近一次操作时间戳 |
| `completed_at` | int | epoch ms ｜ 缺省 | 完成提交时间戳 |
| `reading_time_sec` | int\|null | 秒 | 阅读新闻的时长（performance 计时） |
| `completion_time_sec` | int\|null | 秒 | 从开始到提交的时长 |
| `server_synced` | bool | `false`/`true` | （客户端会话）是否已成功同步到服务端，避免对已同步会话重复提交 |
| `server_received_at` | int\|null | epoch ms | （服务端写入）首次接收时间；以 `participant_id` 幂等写入，重试不更新该时间 |

## 二、`verify` 核查行为日志（核心因变量载体）

| 字段 | 类型 | 说明 |
|---|---|---|
| `verify.reached` | bool | 是否到达核查任务步骤 |
| `verify.declined` | bool | 是否明确点击"暂不查看其他材料" |
| `verify.opened_any` | bool | 是否至少打开过 1 份材料（主 DV 依据） |
| `verify.count` | int | 打开过的材料份数（0–4） |
| `verify.types` | string[] | 打开过的材料标题数组 |
| `verify.order` | string[] | 打开顺序（如 `"A 查看原始实验数据"`） |
| `verify.open` | object | 各材料 key → 是否打开过（`raw`/`inst`/`media`/`fact`） |
| `verify.dwell` | object | 各材料 key → 累计停留秒数（**仅日志，不证明已阅读**） |
| `verify.time` | object[] | `[{type, sec}]`，用于分析各材料停留 |
| `verify.events` | object[] | 完整事件流：`{key, type, action:'open'|'close'|'decline', ts}` |

### 主 DV 与状态字段（务必区分，禁止混编为 0）

| 字段 | 取值 | 含义 |
|---|---|---|
| `verify_status` | `not_reached` | 从未到达核查步骤 |
| | `opened` | 到达且至少打开 1 份材料 → **主 DV `verification = 1`** |
| | `declined` | 到达但明确"暂不查看"（打开数=0） |
| | `skipped` | 到达、未打开任何材料、也未声明"暂不查看"（直接下一步） |
| `verification` | `0`/`1` | 主 DV：**至少打开 1 份 = 1**，其余 = 0 |

> ⚠️ **操作化边界（论文须明确）**：`verification=1` 仅表示"启动核查/主动信息寻求（打开了至少一份补充材料）"，**不等于**"完成独立交叉验证"或"认真阅读了全部内容"。停留时长 `dwell` 仅证明面板被打开过，不证明阅读深度。

### 缺失值规则
- `null`：该题/步骤**未作答或未到达**（如未完成即退出，`status=in_progress` 但无 `completed_at`）。
- `""`（字符串空）：开放题**已到达但未填写**。
- 异常中断记录：`status` 仍为 `in_progress` 且缺少 `completed_at`、各题 `null` → **不得伪装为完整实验**，应在清洗时单独标记（如 `incomplete=true`）后再决定是否剔除。

## 三、CSV 导出列（实验记录 CSV，exp-v2）

顺序：`participant_id, schema_version, AI_label, evidence_consistency, news_version, consent_given, verify_reached, verify_status, verification, verify_count, verify_declined, verify_types, verify_order, verify_time, reading_time_sec, completion_time_sec, status, started_at, last_active, completed_at, server_synced, server_received_at`。

- 数组字段（`verify_types`/`verify_order`/`verify_time`）以 JSON 字符串写入，UTF-8 BOM 便于 Excel 直接打开（服务端 CSV 导出场景）。
- 研究者面板「⑦ 实验参与者数据」为**只读的本地浏览器视图**，展示编号、条件、状态、开始/最后活动/完成时间、到达阶段、核查状态；**不含任何下载按钮**（下载统一由参与者端 XLSX/JSON 完成）。该面板仅读取当前浏览器 `localStorage`，**不跨设备汇总**，界面已注明"仅本浏览器本地记录"。

> 历史 exp-v1 的 CSV 在 `verify_time` 之后还包含 `q1, q2_consistency, q3_resolvability, q4_false_info, ai_awareness, ai_manipulation_check, open_feedback, reading_time_sec` 等问卷列，解析旧文件时按 exp-v1 列序处理即可。

## 四、XLSX 导出（参与者端统一下载）

> 参与者完成实验后，完成页提供「下载我的实验记录（XLSX）」按钮，生成 `experiment_<participant_id>.xlsx`
> （仅含该名参与者一条记录），用于上传至问卷星的**必答文件上传题**。
> 同时保留「下载原始 JSON（备用）」按钮，作为 XLSX 不可用时的兜底。

文件包含三个工作表，表间 `participant_id` 必须完全一致：

### 工作表 1：`participant_summary`（参与者汇总）
- 每名参与者占一行（本导出按单条记录生成，故为一行）。
- 字段顺序（exp-v2，与顶层字段及 CSV 导出保持一致，便于跨格式核对）：
  `participant_id, schema_version, AI_label, evidence_consistency, news_version, consent_given, verify_reached, verify_status, verification, verify_count, verify_declined, verify_types, verify_order, verify_time, reading_time_sec, completion_time_sec, status, started_at, last_active, completed_at, server_synced, server_received_at`
- 数组字段（`verify_types`/`verify_order`/`verify_time`）以 JSON 字符串写入。
- 缺失值沿用顶层字段规则（`null` / `""`），不随意丢弃或改写。

### 工作表 2：`event_log`（行为事件日志）
- 每次材料**打开 / 关闭 / 拒绝继续查看**事件单独占一行，保留原始顺序。
- 字段：`participant_id, seq, key, material_type, action, ts`
  - `seq`：事件序号（从 1 递增，保留重复打开等行为，不合并）。
  - `key`：材料标识（`raw`/`inst`/`media`/`fact`）。
  - `material_type`：材料标题（如「A 查看原始实验数据」）。
  - `action`：`open` / `close` / `decline`。
  - `ts`：事件时间戳（epoch ms）。
- 无关闭事件的材料（如中途退出），其停留时长在原始记录中记为 `null`，**不强行记为 0**；导出时也不补造关闭行。

### 工作表 3：`raw_json`（原始记录备份）
- 每名参与者一行：`participant_id, raw_json`。
- `raw_json` 来自真实实验记录 `JSON.stringify(session)`，不根据汇总表重新拼凑，避免丢失嵌套字段或事件细节。
- **Excel 单元格文本上限 32,767 字符**：导出前检查完整 JSON 长度；若超限，该单元格写入明确说明文字（提示用「下载原始 JSON（备用）」获取完整内容），**绝不静默截断或生成不完整 JSON**。

## 五、与问卷星数据的合并
- 合并键 = `participant_id`（网页生成，问卷星通过 URL 参数带入或参与者手动填入"研究编号"一栏）。
- 实验网页**不再采集**正式问卷答案（理解/卷入/可信度/一致性/可核验/错误判断/AI 标识操纵检验/VOI/AI 态度/人口统计），这些统一由问卷星正式版本采集；请勿将问卷星中被试填写的操纵检验答案反推为实验系统分配的 `assigned_condition`。
- 详见 `docs/问卷星衔接与数据合并说明.md`。

## 六、历史 exp-v1 字段（仅供解析旧导出文件）

exp-v1 的会话与导出中，除上述 exp-v2 字段外，还包含以下由实验网页采集的正式问卷题项（exp-v2 起已迁移至问卷星，不再出现）：

| 字段 | 类型 | 说明（exp-v1） |
|---|---|---|
| `q1` | string\|null | 理解题：护眼模式学生是否报告更舒服 |
| `q2_consistency` | int\|null | 理解题：结果是否一致（1=矛盾,7=支持） |
| `q3_resolvability` | int\|null | 理解题：能否查资料得到更明确判断 |
| `q4_false_info` | string\|null | 理解题：是否存在明显错误信息 |
| `ai_awareness` | string\|null | AI 标识操纵检验（文本） |
| `ai_manipulation_check` | int\|null | AI 标识操纵检验（编码：0=无/不清 ｜ 1=AI辅助 ｜ 2=AI生成 ｜ 9=不清） |
| `open_feedback` | string | 开放题：难以理解之处（可空） |
| `q_reading_option` | string\|null | （临时）阅读理解检查题作答选项 A/B/C/D |
| `q_reading_correct` | bool\|null | （临时）阅读理解题是否答对 |
| `q_reading_ts` | int\|null | （临时）阅读理解题作答时间戳 |
